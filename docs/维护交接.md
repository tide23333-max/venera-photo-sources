## 每次维护流程

1. 核对 git status、当前分支/远程和用户未提交改动。发现不明改动或远程变化停止，不 reset、不覆盖。
2. 在编辑入口修改指定源并提升版本；同步补充 CHANGELOG 和测试状态。
3. 回归解析、真实请求目标、封面/正文请求头、标签/搜索、阅读数组；涉及图片/章节变动要检查首中末页和旧收藏续读。
4. 取得发布授权后，用下面的 prepare 明确生成发布副本与清单，检查差异和隐私。工具默认只验证，不自动准备或推送。

```text
node tools/catalog.mjs --prepare
node tools/catalog.mjs
node tools/catalog.test.mjs
node tools/publish.mjs
```

以上命令在本仓库目录运行。prepare 默认读取同级“网站解析源”；目录不同可显式传入目录参数，不修改脚本内站点地址。

5. 用户确认的正式发布才运行：

```text
node tools/publish.mjs --publish --message "说明具体更新"
```

工具仅提交白名单，检查远程 main 是否仍等于本地基线，不 force-push。存在未提高版本的脚本变化、意外文件、删除/重命名时拒绝发布。

6. 推送后匿名读取 index.json 和本次脚本，核对 key、版本、完整内容和 HTTP 成功；报告提交编号。客户端/手机未操作不得标为通过。

## 失败与回退

- 远程更新冲突：报告并检查，不自动 rebase、merge 或 force-push。
- 提交成功但网络推送失败：已授权提交记录在本地 .git/venera-approved-release；工作区干净、远程没有其他变化时，可用 `node tools/publish.mjs --retry-push` 重试同一提交，不再次改版本/提交。
- 对外发布失败/状态未知：先比较远程 main 与本地提交编号，不连续重复创建仓库或发布。
- 坏版本：本地备份恢复阅读；正式修复提高版本，不能只降清单版本。严禁重建收藏或清空登录来掩盖问题。
- 403/429/验证码停止请求；不导出 Cookie，不连续更换入口绕过限制。

## 测试与隐私说明

检查工具包含保守的凭据/私人地址扫描，不等于完整安全审计。新增字段、手工登录字符串、HTML 样本必须人工核对；命中时只报告文件，不打印秘密值。

公开文档不记录个人阅读内容、账号凭据、私人 IP、应用备份位置或家庭目录。普通发布不请求整站扫描或逐本下载。
